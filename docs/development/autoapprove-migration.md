# Native autoApprove behavior

The Session policy selects native autonomous execution, not a uniform sandbox.
Codex uses approval/sandbox bypass, Kimi native auto mode, and OpenCode v2 retains
native rules while answering active-session-tree requests once. Native refusal
without an Approval Request cannot be approved. Muha makes no cross-Harness
permission-equivalence promise.

Every actual Approval Request keeps a requested/resolved pair; an automatic reply
has source policy only after native success. Questions remain separate with no
Muha implicit timeout. A mode that suppresses Questions does not redefine the
static Profile. Native mode can outlive Muha handle close; close does not revoke it.
Create/resume establishes the selected policy or rejects before exposing a Session.
User/Workspace permission configuration is not rewritten to implement that policy.

Use explicit supported policies for AGY/Pi because Core's default is interactive.
See the [current qualification and limitations](../testing/sdk-qualification.md).
Historic local release formats are not the independent SDK's distribution gate.

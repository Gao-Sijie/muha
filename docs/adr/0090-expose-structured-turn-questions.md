# Expose Structured Turn Questions

Muha V0.1 treats a Harness-originated structured request for user choices or free-form input as a Question, distinct from an Approval Request, and adds paired `question.requested` and `question.resolved` Turn Events plus a Question response operation on `TurnHandle`; the closed Turn Event union therefore grows from fourteen to sixteen kinds. Muha no longer automatically rejects every native Question, and this supersedes ADR-0032's exclusion of generic questions. OpenCode and Kimi Code have native blocking Question protocols that their Adapters map, while occurrence remains optional like reasoning or usage. Exact portable request, answer, resolution, and invalidation payloads are closed by a subsequent decision. Codex MCP elicitation is a separate structured interaction and is not silently classified as a Question by this decision.

The Codex native Adapter keeps its stable-only App Server initialization (`capabilities: null`) and never changes the user's `default_mode_request_user_input` setting. A real Codex 0.158.0 Turn demonstrated that an externally enabled setting can deliver `item/tool/requestUserInput` over this stable-only connection; therefore an experimental method label alone is not evidence that `experimentalApi` opt-in is required for native Questions. The Adapter reads the effective feature value for each created or resumed thread, respecting Codex's trusted project-over-user configuration, and emits a nonblocking Node warning when it is disabled or cannot be verified. This warning is not a substitute for a real positive Question qualification; a disabled setting may leave the declared Question capability untriggered. The ACP bridge's separate experimental connection exception remains scoped by ADR-0137.

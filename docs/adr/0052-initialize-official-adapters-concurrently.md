# Initialize official Adapters concurrently

After host validation, process and data-directory guards, and Diagnostic Event Store initialization succeed, `createMuhaRuntime()` starts every configured official Adapter concurrently with its own `startupTimeoutMs` bound and a Core cancellation signal. The factory succeeds only after every Adapter reports readiness; the first observed failure triggers cancellation of pending starts, but Core waits for every initialization task to settle within its bound, closes every successfully created Adapter, and rejects only after rollback attempts finish. Public failure ordering follows Harness registration order rather than concurrent completion order, preserving all-or-nothing Runtime creation while bounding normal multi-Harness startup by the slowest Adapter instead of the sum of their bounds.

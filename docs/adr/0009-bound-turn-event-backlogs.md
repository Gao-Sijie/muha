# Bound Turn event backlogs

Muha Core will bridge native event producers to each Turn Handle through a queue bounded by both serialized event count and UTF-8 JSON bytes, defaulting to 4,096 events and 16 MiB per Turn and using lossless coalescing where possible. Callers may tune both bounds in Runtime configuration and must drain this live stream while the Turn runs: `TurnHandle.result` is a terminal-value channel rather than a non-streaming execution API, and V0.1 provides neither automatic draining nor a `runTurn` shortcut. If either queued bound is exceeded, Core interrupts and fails the Turn with a backpressure error; if one normalized event alone exceeds the byte bound, Core records the complete Native Event Record but fails with an event-too-large error instead of truncating or enqueueing that Turn Event. Core reserves capacity for the terminal error event rather than silently dropping data, allowing unbounded memory growth, or adding persistent public-event storage to the SDK.

# Normalize approval handling, not permission rules

The request-only `autoApprove` and no-bypass decisions below are superseded by
[ADR-0119](0119-select-native-autonomous-execution-through-auto-approve.md) for
V0.1.12. Other policies and one-shot decisions retain their existing meaning.

Muha's portable contract will expose `ApprovalPolicy` with `interactive`, `autoApprove`, and `autoDeny` modes, defaulting to `interactive` when Session creation or resumption omits it. The policy applies only to the current live Session run and is not persisted in the Workspace or inferred from a native Session's prior mode. ADR-0072's complete Agent Session surface supersedes the former setter: changing policy requires closing the handle and resuming the native Session with a new policy. It takes effect only after a Harness originates an Approval Request: interactive mode surfaces it to the caller, while the automatic modes respond with one-shot allow or deny decisions. Public `ApprovalDecision` values are limited to `allowOnce` and `deny`; persistent vendor decisions are excluded, and callers interrupt the Turn instead of sending a vendor-specific cancellation decision. Each request id can be resolved once, while duplicate, unknown, and invalidated responses fail with structured errors. An interactive request has no implicit timeout and remains pending until the caller responds, interrupts the Turn, or closes the Session. Muha does not map `autoApprove` to vendor full-access, YOLO, or permission-bypass modes, and does not claim to normalize approval triggers, persistent allow rules, tool matchers, sandboxing, network authority, or plan-mode controls.

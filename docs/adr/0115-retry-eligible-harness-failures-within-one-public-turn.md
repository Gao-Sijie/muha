# Retry Eligible Harness Failures Within One Public Turn

Muha Core owns opt-in Turn retry supervision as a process-local Agent Session policy while each Harness Adapter remains responsible only for translating native failure classification. Every accepted Turn keeps one public identity, one `turn.started`, a contiguous event sequence, cumulative usage, zero or more `turn.retrying` observations, and one matching terminal Result while Core may execute multiple private Turn Attempts. The policy defaults to zero retries, gives every Turn a fresh bounded budget, treats `retryable: false` and unresolved Approval or Question interactions as vetoes, and is supplied independently on Session creation or resumption rather than persisted in Session Reference. This extends ADR-0033, ADR-0035, ADR-0055, ADR-0072, ADR-0074, and ADR-0080, accepting at-least-once duplicate messages, Tool activity, and external side effects in exchange for caller-controlled availability.

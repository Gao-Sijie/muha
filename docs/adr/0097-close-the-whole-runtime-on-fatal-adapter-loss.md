# Close the Whole Runtime on Fatal Adapter Loss

After initialization, an unexpected exit of any Adapter-owned Harness process or permanent loss of its control channel is fatal to the complete Muha Runtime. Core automatically enters the same irreversible close path as caller-requested closure: active Turns directly affected by the loss fail first with `HARNESS_ERROR`, other active Turns are interrupted with `runtimeClosed`, all pending Approval Requests and Questions resolve or invalidate before their terminal events, and every Session handle, Adapter, Event Store, and guard is closed. Muha V0.1 neither restarts a Harness nor keeps a degraded Runtime with fewer Harnesses; the Runtime still transitions only `active → closing → closed`. Native Sessions remain untouched and can be explicitly resumed through a newly created Runtime.

An Adapter with independently owned Session processes may identify the directly affected Adapter Session handles in its private fatal report; omitted scope retains the existing whole-Harness interpretation. Handle identity, not native Session ID, distinguishes separately owned processes even when they resume the same conversation, and Core applies this rule without Harness-specific branches.

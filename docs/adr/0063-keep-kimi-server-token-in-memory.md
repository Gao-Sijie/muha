# Keep the Kimi Server Token in Memory

The Kimi Adapter parses the bearer token and origin from the `kimi web` ready output, retains them only in Adapter memory until shutdown, and reacquires them from native ready output on every new Runtime. The token is persistent native Harness state created and reused by Kimi Code in its own home-directory `server.token`; Muha does not create, rotate, delete, or copy that file and does not claim that the credential is ephemeral. It never writes the token or ready banner to the Diagnostic Event Store, another Muha file, a public event, or an error message. Native Event Records remain complete and unredacted because they contain protocol events received after connection, whereas child-process ready banners, stdout/stderr logs, and other control-plane output are drained for lifecycle management but are neither Native Events nor persistently logged by Muha.

# Make the Turn Handle the Single Event Iterator

`TurnHandle` exposes read-only `turnId: string`, `result: Promise<TurnResult>`, idempotent `interrupt(): Promise<void>`, and `respondToApproval(requestId, decision): Promise<void>`, and itself implements `AsyncIterable<TurnEvent>` as its only event-consumption surface. Exactly one iterator may be claimed per Handle and another claim throws `TURN_EVENT_STREAM_ALREADY_CLAIMED`; awaiting `result` neither consumes nor drains events, leaving a non-consuming caller subject to normal Turn backpressure. Leaving iteration early neither interrupts nor drains the Turn. Approval Decisions are exactly `"allowOnce" | "deny"` and may target only a still-pending request in that Turn; a rejected Approval command does not by itself terminate the Turn. The terminal event is the final iterable value and exactly matches the always-resolving terminal result. V0.1 exposes no callback subscription, EventEmitter, separate `events` property, Handle `close`, or native Turn handle.

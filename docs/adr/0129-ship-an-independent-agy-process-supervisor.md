# Ship an independent AGY process supervisor

The AGY Adapter ships a small Linux x64 executable that becomes a subreaper only inside its own process and starts the caller's native CLI with the supplied environment and Workspace. Its single reaper signals only its own unreaped children, repeats adoption and reclamation, and confirms success only at `ECHILD`; helper exit zero independently confirms that condition if the final control response is lost. The consuming Node process retains its own signals, child ownership, environment, and working directory, and ADR-0128 continues to exclude complete reclamation after the helper itself dies.

The package build compiles the helper and includes the executable and its source in the local artifact; consumers need neither a compiler nor Python, systemd, namespace privileges, or a new kernel facility beyond the existing Linux platform. The helper dynamically links the platform glibc and binds the preserved x86-64 startup ABI, with no application constructors; the build checks that required glibc symbols do not exceed the existing 2.28 floor. The complete ownership matrix was also executed with an actual glibc 2.28 loader, and changes to startup or constructors must retain that qualification rather than infer compatibility from symbol names alone.

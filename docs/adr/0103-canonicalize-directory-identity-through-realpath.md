# Canonicalize Directory Identity Through Realpath

Muha accepts absolute Workspace and `dataDir` inputs that may contain symbolic links, but after an applicable directory exists or has been created, Core resolves it with `realpath` and uses that canonical absolute path for public values, Session References, Harness operations, serialization keys, and storage ownership. Different aliases of one existing directory therefore have one Muha identity, and later retargeting a symbolic link does not move an already-bound Session. `listSessions` remains the sole operation that permits a missing Workspace directory; because no filesystem object then exists to resolve, Core uses the lexically normalized absolute input and callers should provide the canonical path retained in an earlier Session Reference. Muha does not reconstruct the former target of a missing or broken symbolic link. This sharpens the earlier uses of “normalized path” in ADR-0021, ADR-0027, ADR-0048, ADR-0056, ADR-0066 through ADR-0068, ADR-0084, and ADR-0101.

# Adopt behavior-preserving ACP-first routes

Status: superseded by [ADR-0140](0140-admit-harnesses-by-muha-contract-conformance.md) for the first-version qualification gate. The historical ACP-first work and evidence remain in the [development plan (historical private reference)](../testing/private-history.md).

Amendment (2026-09-17): [ADR-0135](0135-reset-muha-artifacts-to-one-session-reference-format.md) replaces the legacy Muha-reference compatibility language below with one unversioned four-field reference and explicit rejection of old Muha formats; native Harness continuity and all other behavior-preservation requirements remain in force.

Muha evaluates all five existing Harness Adapters before internal delivery acceptance and prefers ACP while preserving the current Core Kernel and each Adapter's complete static Capability Profile, allowing native operations alongside ACP only where shared native Session identity, configuration, permissions, and execution ownership are verified. Muha selects the Harness Integration Route rather than exposing a public protocol selector, retains an interpretable route identity in Session References and diagnostics with deterministic legacy-reference handling, and treats ACP negotiation as an internal compatibility check rather than a new public dynamic-capability API or permission to silently downgrade behavior or retry across routes. Evidence-backed native retention can qualify and Pi may retain its verified, patched SDK when official ACP support is insufficient, but an unavailable validation environment remains blocked rather than proving ACP unsuitable; this accepts additional integration work to preserve existing SDK behavior and session continuity.

This preserves [ADR-0118](0118-declare-and-enforce-static-harness-capabilities.md)'s static declaration model and [ADR-0005](0005-keep-native-harnesses-authoritative-for-sessions.md)'s native Session authority; the exact Reference extension and per-Harness route changes must be specified before switching defaults, and current V0.1 references still use their existing three-field representation.

# Validate AGY resume with read-only native metadata

AGY stage five may read native private Session and Project metadata inside the Adapter to verify known-reference identity, existence, and Workspace ownership without an SDK or Muha-maintained Session Index. This accepts native-format compatibility costs because the CLI can silently create a different conversation for an unresolved ID and cwd alone does not prove the native Workspace binding. Unrecognized or unusable metadata fails explicitly rather than being guessed, rewritten, repaired, or silently skipped; permission to investigate and depend on this metadata is not evidence that a reliable parser has already been established.

Resume prechecks existence and validates the native identity returned at startup. If a race still causes native creation of a different empty conversation, the Adapter closes it, submits no user input, and reports failure; the accepted policy tolerates that residual native record rather than attempting automatic history deletion. Externally created Sessions are not rejected solely for their provenance, but their identity and Workspace ownership must be reliably established.

Each newly created Muha AGY Session uses an independent native Project bound to its Workspace; resume retains the original native Project. Closing a Session or Runtime does not delete native Projects or conversation history, and stage five adds no automatic Project garbage collection. Intentional interruption may use controlled process replacement under the same public Session handle and native conversation ID; unexpected process loss still follows ADR-0097, and neither replacement nor metadata validation weakens complete Kernel conformance or owned-process cleanup requirements.

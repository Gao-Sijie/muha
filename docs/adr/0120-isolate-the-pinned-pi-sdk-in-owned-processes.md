# Isolate the pinned Pi SDK in owned processes

For the stage-four Pi integration specified by issue #85, the official Pi Adapter directly depends on a pinned official SDK distribution and uses Adapter-owned Node processes rather than a PATH CLI; this is a Pi-only exception to ADR-0059/0060, not a change to other Harnesses. Session execution, initialization checks and listing workers remain owned resources, while only the consuming main process owns the Muha Runtime and Diagnostic Event Store; process isolation is lifecycle isolation, not a security sandbox. Pi may natively install and load extensions, including MCP extensions, but Muha neither manages them nor declares Workspace MCP support on that account.

Pi's native Bash tools create detached process groups, so terminating only the SDK group is insufficient after SDK process loss. The owned worker observes Node child creation without changing spawn options, and the Adapter retains detached-group identities for shutdown reclamation, checking Linux process birth identity before signaling a still-present leader; this lifecycle bookkeeping does not alter the SDK source patch or claim containment of adversarial native extensions.

The owned Session observes promises returned by its public high-level prompt method as well as SDK idle settlement: native extension commands return before their own sendUserMessage preflight necessarily finishes. Cancellation is checked at native preflight acceptance so a delayed extension request cannot start after the public Turn has been interrupted; the Adapter neither copies the agent loop nor substitutes low-level message submission.

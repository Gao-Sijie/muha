# Expose a Non-Rejecting Runtime Termination Signal

`MuhaRuntime` exposes one read-only `termination` Promise that settles exactly once after all automatic or caller-requested closure work has completed and never rejects. Its terminal value distinguishes caller closure from fatal closure, carries the original existing `HARNESS_ERROR` or `EVENT_STORE_ERROR` for a fatal trigger, and can additionally carry the existing `RUNTIME_CLOSE_FAILED` when cleanup was incomplete; the first accepted fatal trigger is authoritative. `runtime.close()` remains the active, idempotent cleanup command with its existing rejection behavior, while `status` remains the synchronous snapshot. This adds no error taxonomy and no Runtime event stream, avoids unhandled Promise rejections when callers do not observe it, and gives idle long-running consumers a channel for asynchronous fatal closure. This supersedes ADR-0067 only where that ADR called the former Runtime member list complete.

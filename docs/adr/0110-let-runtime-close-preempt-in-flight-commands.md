# Let Runtime Close Preempt In-Flight Commands

Caller-requested or fatal Runtime close is the highest-priority cancellation boundary. Once Core accepts closure, every ordinary command that has not yet returned its Handle or final result is cancelled and rejects with `RUNTIME_CLOSED`; already-returned Turn Handles instead receive their established `runtimeClosed` interrupted terminal value before cleanup. Workspace configuration, Session creation, or another native command may already have made partial native side effects before acknowledgement, but Muha neither rolls them back nor synthesizes success. A later Runtime can rediscover only what the authoritative Harness exposes through list or resume. Runtime close never waits for the fixed one-hour command or configuration watchdogs and remains governed by each Adapter's 60-second shutdown bound.

# Use the native AGY CLI without an SDK fallback

The stage-five AGY Adapter uses the caller-installed and authenticated `agy` executable discovered through `PATH`, continuing ADR-0059 and ADR-0060. The user explicitly excludes the SDK/API-billed integration route, so neither a direct SDK dependency nor an SDK fallback may be used to fill CLI gaps; the Pi-only exception in ADR-0120 does not extend to AGY. Version 1.1.25 is the requested development reference, not a pinned executable or version-admission gate; evidence collected against another installed version must identify that version rather than imply qualification of 1.1.25.

AGY's native Project binding stays within the Harness Adapter: callers continue supplying the existing Workspace path and Session Reference, and Core Kernel gains neither a Project lifecycle nor AGY-specific behavior. This boundary does not settle native Project creation, reuse, retention, or resume-validation policy. The first AGY Profile will declare `sessionListing: false`; known-reference resume remains mandatory, and CLI or native-metadata limitations cannot be hidden by silently creating replacement conversations or weakening Kernel conformance.

# Decline MCP Elicitation in V0.1

Muha V0.1 exposes no MCP elicitation interaction. When the stable Codex app-server forwards a standard form or URL-mode `mcpServer/elicitation/request`, the Codex Adapter records the complete native request, immediately responds with native action `"decline"` and null content, records the native resolution, and emits no Question, Approval, or other public event. It does not opt into Codex's extended `openai/form` variant. This prevents a Turn from hanging while preserving ordinary MCP tool execution; an MCP tool that requires elicitation receives a native refusal and may fail normally. OpenCode and Kimi Code currently do not advertise an MCP elicitation client capability, so their servers should reject elicitation at protocol negotiation rather than forward a blocking request. Full schema-driven forms and URL flows require a future separately typed Capability and are not partially mapped to Question in V0.1.

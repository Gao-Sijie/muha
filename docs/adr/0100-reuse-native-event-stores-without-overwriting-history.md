# Reuse Diagnostic Event Stores Without Overwriting History

A caller may reuse an explicit Runtime `dataDir` after the previous Runtime using it has completely closed. Every new Runtime receives its own Runtime ID and appends Diagnostic Event Records to the existing SQLite store without overwriting or assuming ownership of earlier Runtime history. Core may transactionally migrate supported older schemas during startup, with the whole migration committed or rolled back atomically. Corruption, failed integrity validation, or a newer unrecognized schema rejects Runtime initialization; Muha never automatically deletes, recreates, downgrades, or best-effort repairs the database. The caller may recover, archive, or replace storage only while no Runtime is using that directory.

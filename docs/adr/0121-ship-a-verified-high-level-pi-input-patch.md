# Ship a verified high-level Pi input patch

The Pi Adapter builds a bounded high-level input patch against the exact SDK source digest and ships the resulting module and upstream license. It declares the exact SDK version as an ordinary npm dependency rather than bundling the SDK tree; an Adapter-owned process verifies the installed package version and source digest, then loads the one patched module at its native module URL before importing the SDK, without editing installed dependencies or copying the agent loop. This preserves the patch while leaving ordinary dependency installation to npm. An ordered input is projected to newline-joined text and ordered images for native command, input-hook and template processing: absent a native transformation its original parts remain the user message, while an explicit input-hook transformation or actual Skill/template expansion supplies the native replacement text-and-images message; legacy string input remains unchanged. Ordered input cannot use native steering/follow-up options, which are outside Muha's single-active-Turn contract, and build/loader integrity failures never fall back to an unpatched SDK.

This records the implementation mechanism for #87, not completed qualification of #85: the full Muha Adapter, native transformation combinations, image rejection, independent installation and lifecycle contracts still require their specified tests. The upstream license is retained from the Pi v0.84.2 MIT distribution.

Build generates the patch before execution; prepack only verifies the locked SDK source, prepared patch and private worker modules and fails when they are missing or stale. The patched module still contains substantial Pi source, so its upstream license remains in the Muha artifact. Prepublication local candidates need Registry access or a prewarmed npm cache for this dependency; the seven Muha tarballs are not an offline installation set.

The former SDK copy step was removed after repeated builds were observed to interrupt concurrent consumers' module loading. Unchanged generated modules are not rewritten; an actual SDK/source upgrade still requires a new verified patch and requalification before starting consumers.

# Leave AGY native plugins and permission rules unmanaged

AGY stage five preserves native environment, login, plugin, hook, rule, and subagent loading rather than introducing an isolated profile or Muha plugin manager. Users and their Sessions may use native facilities to install or change these resources under native permissions; Muha neither adds a plugin allowlist nor promises rollback, immediate reload, arbitrary plugin compatibility, or a security sandbox. This accepts native configuration's influence on execution while retaining Muha's Kernel, event, failure, and owned-process cleanup obligations.

Muha manages only explicitly requested Workspace Skills through the existing ADR-0004/0024 contract and the native Project binding established in ADR-0125. Unrelated Skills and configuration remain untouched; empty configuration inputs do not clear native resources. `workspaceMcp: false` rejects Muha requests to configure AGY MCP without disabling MCP already supplied by users or native plugins. There is no automatic configuration synchronization or Session restart for Skill changes.

`harnessManaged` delegates permission execution to native configuration without Muha's autonomous-mode override; the accepted `autoApprove` target is AGY's `--dangerously-skip-permissions` on creation, resume, and intentional process replacement. Current Session-run selections must be established rather than accidentally inherited, without implementing policy through persistent global, Workspace, or existing Project permission-rule edits. Native persistence is not rolled back on close, and native denial is not a fabricated Approval Request or successful approval. This boundary does not settle unverified skip/deny/sandbox/review precedence or substitute for policy-transition qualification.

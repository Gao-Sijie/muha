# Integrate Kimi Code Through Its Local Server

The official Kimi Adapter manages one authenticated loopback Kimi Code child process started with `kimi web --no-open --host 127.0.0.1 --port 0`, uses `/api/v1` REST for readiness, Workspace registration, Session creation and listing, prompt submission, interruption, and Approval Decisions, and consumes the WebSocket v2 Session event stream for ordered native activity and resynchronization. It never disables bearer authentication, treats native Kimi Sessions as authoritative, drains native pagination internally, and subjects the child process to Muha's bounded Adapter startup and shutdown lifecycle. The Adapter owns a small runtime-validated wire client but applies no Kimi Code version range or startup capability matrix beyond reaching its basic authenticated REST readiness; it does not depend on `@moonshot-ai/kimi-agent-sdk`, ACP, or Kimi Code's private monorepo SDK, protocol, or server packages in V0.1.

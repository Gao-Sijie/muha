# Use a closed V0.1 error-code set

Muha V0.1's `MuhaErrorData` is a closed discriminated union with 25 codes: `INVALID_INPUT`, `UNSUPPORTED_PLATFORM`, `UNSUPPORTED_RUNTIME`; `RUNTIME_ALREADY_ACTIVE`, `RUNTIME_CLOSED`, `RUNTIME_INITIALIZATION_FAILED`, `RUNTIME_CLOSE_FAILED`, `DATA_DIR_LOCKED`, `HARNESS_NOT_ENABLED`; `WORKSPACE_NOT_FOUND`, `WORKSPACE_IO_ERROR`, `SKILL_CONFIGURATION_FAILED`, `MCP_CONFIGURATION_FAILED`; `SESSION_NOT_FOUND`, `SESSION_CLOSED`, `SESSION_BUSY`; `TURN_EVENT_STREAM_ALREADY_CLAIMED`, `TURN_INTERACTION_NOT_FOUND`, `TURN_INTERACTION_ALREADY_RESOLVED`, `TURN_INTERACTION_INVALIDATED`; `HARNESS_ERROR`, `ADAPTER_PROTOCOL_ERROR`, `EVENT_STORE_ERROR`; and `TURN_EVENT_BACKPRESSURE`, `TURN_EVENT_TOO_LARGE`. The three shared Turn Interaction codes are the ADR-0095 replacements for the former Approval-only codes. Every member shares only a stable `code` and a developer-facing, non-stable `message`; there is no common details object, cause, stack, timestamp, correlation identifier, or retry flag, although `HARNESS_ERROR` may carry `retryable` when the Adapter can determine it. `UNSUPPORTED_RUNTIME` carries `runtime: "node"`, the observed `version`, and `supportedRange: ">=22.20.0"`. `RUNTIME_INITIALIZATION_FAILED` contains a non-empty, deterministically ordered list of typed Harness-initialize or Event Store-open failures plus a possibly empty list of typed rollback failures. `RUNTIME_CLOSE_FAILED` contains a non-empty, deterministically ordered list of typed Harness-close and Event Store failures collected only after every cleanup attempt completes, and `EVENT_STORE_ERROR.operation` includes `open`, `write`, `commit`, and `close`. Muha does not create separate codes for Harness-native model, authentication, network, rate-limit, individual operation failures, or unsupported optional capabilities: native rejections remain typed `HARNESS_ERROR` values with an operation and optional native code, while protocol violations retain their distinct Core meaning.
